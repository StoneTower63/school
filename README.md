# Hogwarts School API — Спецификация и Технический Паспорт Проекта

RESTful API [рэ́стфул эй-пи-ай] веб-приложение для автоматизации учета и управления цифровой картотекой сущностей
проекта Hogwarts. Серверная часть реализована на стеке Spring Boot 3.3.0 с использованием архитектурного шаблона MVC (
Model-View-Controller) и объектно-реляционного отображения (ORM).

## 🚀 1. Стек технологий и Системное окружение

* **Java 17 (Amazon Corretto)** — среда исполнения и виртуальная машина (JVM).
* **Spring Boot 3.3.0 (Starter Web, Starter Data JPA, Starter Test)** — базовый фреймворк приложения.
* **PostgreSQL 15** — реляционная система управления базами данных (СУБД).
* **Hibernate / JPA** — ORM-движок автоматического управления и синхронизации схем таблиц (режим
  `spring.jpa.hibernate.ddl-auto=validate`).
* **Apache Maven** — инструмент автоматизации сборки и управления зависимостями.
* **Jackson (ObjectMapper)** — библиотека сериализации/десериализации данных в формат JSON.
* **Springdoc OpenAPI v2 (Swagger UI)** — генерация интерактивной документации веб-интерфейсов API.
* **JUnit 5 / AssertJ / Mockito** — программная среда модульного, изолированного и интеграционного тестирования.

## 🏗️ 2. Архитектура и Слоевая Изоляция (Layered Architecture)

Компоненты приложения разделены на изолированные слои с целью минимизации зацепления (coupling):

* **model (Слой данных)** — JPA-сущности Student, Faculty и Avatar. Отношения между таблицами настроены через аннотации
  @ManyToOne, @OneToMany и @OneToOne. Для оптимизации расхода оперативной памяти (RAM) и предотвращения утечек памяти (
  класса OutOfMemoryError) для связей задана ленивая загрузка FetchType.LAZY.
* **repository (Слой доступа к данным)** — интерфейсы доступа к СУБД, наследующие JpaRepository и
  PagingAndSortingRepository. Фильтрация данных переведена на нативный SQL-движок через аннотации @Query(nativeQuery =
  true).
* **service (Слой бизнес-логики)** — компоненты @Service, инкапсулирующие логику обработки данных и потоков
  ввода-вывода (I/O Streams). Реализована валидация входных параметров с генерацией исключений IllegalArgumentException
  при обнаружении null-значений или пустых выборок. Внедрение зависимостей репозиториев выполнено строго через private
  final поля и конструкторы классов.
* **controller (Веб-слой)** — сетевые диспетчеры @RestController для обработки входящих HTTP-запросов. Компоненты
  находятся в рамках паттерна "тонких контроллеров" (вызов методов сервисного слоя в одну строку). Прямое использование
  ResponseEntity ограничено механизмами выгрузки бинарных файлов (InputStreamResource).

## 🛠️ 3. Спецификация веб-интерфейсов (REST API)

### Сущность Студенты (`/student`)

* `POST /student` — Регистрация новой записи. Возвращает Long id со статусом 201 Created через аннотацию
  @ResponseStatus.
* `GET /student/{id}` — Поиск записи по первичному ключу ID с защитой от null.
* `PUT /student` — Полное обновление полей существующей сущности. Возвращает обновленный объект.
* `DELETE /student/{id}` — Удаление записи по ID. Возвращает void со статусом 204 No Content (@ResponseStatus).
* `GET /student?min=10&max=15` — Фильтрация записей по диапазону возрастов. Выполняется силами СУБД (Java Streams не
  используются).
* `GET /student/{id}/faculty` — Получение связанного объекта Faculty для конкретного ID студента через прокси-ссылку.
* `GET /student/count` — Нативный SQL-запрос `COUNT(*)` для подсчета общего количества записей в таблице.
* `GET /student/average-age` — Нативный SQL-запрос `AVG(age)` для расчета среднего возраста. Реализована обработка
  пустой БД (возврат значения 0.0).
* `GET /student/last-five` — Нативный SQL-запрос выборки пяти последних добавленных записей через сортировку
  `ORDER BY id DESC LIMIT 5`.

### Сущность Факультеты (`/faculty`)

* Полный CRUD-цикл (`POST` возвращает Long id, статус 201; `GET` возвращает объект, статус 200; `PUT` возвращает
  обновленный объект; `DELETE` возвращает void, статус 204).
* `GET /faculty?nameOrColor=Gryff` — Регистронезависимый поиск совпадений по подстроке в полях имени или цвета на уровне
  SQL-запроса.
* `GET /faculty/{id}/student` — Возврат коллекции студентов, привязанных к целевому ID факультета.

### Сущность Аватары и Механизмы Пагинации (`/avatar`)

* `POST /avatar/{studentId}` — Загрузка медиафайла через MultipartFile. Файл сохраняется дублированно: в файловую
  систему Mac (буферный каталог) и в виде байтового массива byte[] в таблицу СУБД (поле под аннотацией @Lob).
* `GET /avatar/{studentId}/from-db` — Выгрузка бинарных данных из СУБД. Возвращает ResponseEntity с заполнением
  HttpHeaders (Content-Type, Content-Length) для корректного парсинга операционной системой.
* `GET /avatar/{studentId}/from-file` — Потоковая передача данных с диска через HttpServletResponse.getOutputStream() и
  transferTo(), исключающая перегрузку Heap-памяти.
* `GET /avatar?page=0&size=5` — Постраничный вывод списков аватарок. Метод принимает параметры номера страницы `page` (
  индексация с 0) и размера выборки `size`. Контроллер вызывает метод сервиса, возвращающий List<Avatar> через метод
  .getContent() объекта PageRequest.

## 🏗️ 4. Инфраструктура Автоматического Тестирования

Покрытие логики тестами реализовано в рамках двух изолированных подходов:

### 🟥 Интеграционное тестирование (Компонент `TestRestTemplate`)

* Запуск приложения в изолированном контексте JVM на случайном порту оперативной памяти (
  `webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT`).
* Сквозная проверка CRUD-операций контроллеров в связке с реальной базой данных PostgreSQL 15.
* Интеграция каскадной очистки репозиториев перед каждым тестовым методом для исключения ошибок целостности Foreign Key
  Constraints.

### 🟩 Изолированное тестирование веб-слоя (Компонент `MockMvc`)

* Использование аннотации `@WebMvcTest` для проверки веб-интерфейсов без развертывания тяжеловесных контекстов СУБД.
* Замещение сервисного слоя мок-заглушками `@MockBean` с программированием сценариев через
  `Mockito.when().thenReturn()`.
* Верификация структуры ответов серверов по строгим путям JSON-синтаксиса (`$.name`, `$[0].color`).

## 🎛️ 5. Глобальная обработка исключений (Exception Handling)

Внедрен централизованный механизм перехвата контролируемых ошибок на уровне контроллеров:

```java

@ExceptionHandler(IllegalArgumentException.class)
@ResponseStatus(HttpStatus.BAD_REQUEST)
public String handleIllegalArgumentException(IllegalArgumentException ex) {
    return ex.getMessage();
}
```

**Физический смысл:** Исключения `IllegalArgumentException`, генерируемые сервисным слоем при отсутствии сущностей в БД,
перехватываются обработчиком в памяти RAM, трансформируясь в валидный HTTP-статус `400 Bad Request` с возвратом
текстового описания причины ошибки клиенту.

## 📊 6. Скрипты Управления Схемами и Реляционной Аналитики

Для ручного конфигурирования схем данных и тестирования в СУБД, в корневом каталоге проекта размещены файлы
SQL-скриптов:

* **`scripts.sql`** — Базовые аналитические SELECT-запросы к таблицам СУБД.
* **`scripts421.sql`** — Инструкции ALTER TABLE для модификации схемы существующих таблиц:
    * Добавление логического ограничения `CHECK (age >= 16)`.
    * Установка ограничений `ALTER COLUMN name SET NOT NULL` и `UNIQUE` на поле имени.
    * Создание составного уникального ключа `UNIQUE (name, color)` для таблицы факультетов.
    * Инициализация значения по умолчанию `SET DEFAULT 20` для поля возраста студентов.
* **`scripts422.sql`** — DDL-скрипт проектирования нормализованной схемы данных связи "Многие к Одному" (Many-to-One)
  между сущностями водителей и автомобилей со строгим соблюдением типов данных (`BIGSERIAL`, `INT`, `BOOLEAN`,
  `NUMERIC`, `BIGINT REFERENCES`).
* **`scripts423.sql`** — DML-запросы с использованием синтаксиса `INNER JOIN` для реляционного объединения таблиц без
  использования избыточного оператора `*`.

## 📦 7. Автоматическое управление схемами и индексация (Liquibase)

Управление структурой реляционных таблиц переведено под строгий контроль системы миграций Liquibase в обход
автогенерации Hibernate (режим `spring.jpa.hibernate.ddl-auto=validate`).

### Архитектура файлов миграций:

* **`changelog-master.yml`** — главный диспетчерский пульт управления, координирующий последовательный вызов и накат
  внешних скриптов изменений.
* **`index-practice.sql`** — нативный SQL-миграционный файл сценариев, разделенный на изолированные транзакционные
  блоки (`changeset`):
    * `changeset asmirnov:1` — физическая инициализация одиночного B-tree индекса `idx_student_name` на таблицу
      `student` по колонке `name`. Оптимизирует скорость сквозного поиска студентов по их именам.
    * `changeset asmirnov:2` — физическая инициализация составного (композитного) B-tree индекса
      `idx_faculty_name_color` на таблицу `faculty` по координирующим колонкам `name, color`. Исключает полный перебор
      строк СУБД при сложной фильтрации факультетов по связке имени и цвета.

## 🖥️ 8. Регламент Запуска и Инфраструктурный Аудит

### ⚠️ Требования к техническому окружению

* **Кодировка файлов:** Файлы `application.properties` (каталоги main и test) обязаны иметь кодировку UTF-8 и тип
  перевода строк LF. Наличие скрытых байт CRLF приводит к критическому сбою парсинга конфигурации.
* **VM Options / Environment Variables:** В конфигурацию запуска IDE (Edit Configurations) должен быть передан явный
  параметр локального пути к директории хранения файлов: `path.to.avatars.folder=./avatars`.
* **🛑 Протокол аудита сбоев:** При падении контекста (ошибки класса "Could not resolve placeholder") запрещено вносить
  хаотичные изменения в Java-код. Проводится системная пошаговая изоляция внешних факторов: Кодировка .properties ->
  Очистка кэша сборщика (Maven Lifecycle clean) -> Валидация VM-параметров запуска в IDE -> Проверка прав доступа ОС на
  чтение/запись папки ./avatars.

### 📌 Инструкция по запуску

1. Выполнить форматирование кодовой базы по сочетанию горячих клавиш **`⌥⌘L`** (Option + Command + L).
2. Запустить синтаксическую компиляцию и сборку проекта без старта веб-сервера через сочетание **`⌘F9`** (Command + F9).
   Сборщик должен вернуть `Exit code: 0`.
3. Запустить главный класс `SchoolApplication` кликом по кнопке Run графического интерфейса IDE (сочетание **`⌃R`**).
4. Веб-интерфейс тестирования доступен по локальному
   адресу: [http://localhost:8080/swagger-ui/index.html](http://localhost:8080/swagger-ui/index.html)
