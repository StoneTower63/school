# 🧙‍♂️ Hogwarts School API — Enterprise Management System

Веб-приложение для автоматизации и управления цифровой картотекой Школы Чародейства и Волшебства «Хогвартс». Проект реализован на фреймворке **Spring Boot 3.3.0** с использованием архитектуры **MVC** (Model-View-Controller) и объектно-реляционного отображения (ORM).

---

## 🚀 1. Стек технологий и Окружение
* **Java 17** (Amazon Corretto) — среда исполнения виртуальной машины (JVM).
* **Spring Boot 3.3.0** (Web, Starter Data JPA, Starter Test) — ядро экосистемы приложения.
* **PostgreSQL 15** — промышленная реляционная система управления базами данных (СУБД).
* **Hibernate / JPA** — движок ORM для автоматического управления схемами таблиц в режиме `update`.
* **Maven** — автоматизированный сборщик проекта и управления зависимостями.
* **Jackson (ObjectMapper)** — сериализация и десериализация объектов в текстовый JSON-формат.
* **Springdoc OpenAPI v2 (Swagger UI)** — интерактивный фронтенд документации и тестирования API.
* **JUnit 5 / AssertJ / Mockito** — стек модульного, веб-изолированного и интеграционного тестирования.

## 🏗️ 2. Архитектура проекта и Слоевая Изоляция
Проект разделен на четыре независимых слоя по стандарту Enterprise-разработки для минимизации зацепления (coupling):

1. `model` (Слой данных) — реляционные сущности `Student`, `Faculty` и `Avatar` с настроенными связями `@ManyToOne`, `@OneToMany` и `@OneToOne`. Все объектные графы защищены ленивой загрузкой `FetchType.LAZY` для предотвращения переполнения оперативной памяти RAM, утечек памяти и критических ошибок `OutOfMemoryError`.
2. `repository` (Слой доступа к БД) — интерфейсы, наследующие `JpaRepository` для автоматической генерации быстрых SQL-запросов. Фильтрационные методы полностью переведены на нативный SQL-движок базы данных через аннотации `@Query(nativeQuery = true)`.
3. `service` (Слой бизнес-логики) — компоненты `@Service`, управляющие логикой через БД и потоки ввода-вывода `I/O Streams`. На уровне сервисов реализована жесткая страховка от `null`-значений в памяти Heap через автоматический выброс контролируемых `IllegalArgumentException`.
4. `controller` (Веб-слой) — сетевые диспетчеры `@RestController` для обработки HTTP-запросов по REST-стандарту. Согласно критериям кураторов SkyPro, контроллеры находятся "на диете" (логика метода содержит строго одну строку вызова сервиса), а использование `ResponseEntity` запрещено везде, кроме эндпоинтов выгрузки бинарных файлов.

## 🛠️ 3. Функционал API (CRUD + Фильтрация и Связи)

### Студенты (`/student`)
* `POST /student` — Создать студента. Возвращает строго чистый `Long id` со статусом `201 Created` (`@ResponseStatus`). Использование `ResponseEntity` запрещено.
* `GET /student/{id}` — Получить полную информацию о студенте по его ID из базы данных (защищено от `null`).
* `PUT /student` — Обновить данные мага. Возвращает полностью обновленный объект сущности (все поля).
* `DELETE /student/{id}` — Удалить карточку студента из PostgreSQL. Возвращает `void` со статусом `204 No Content` через `@ResponseStatus`.
* `GET /student?min=10&max=15` — Оптимизированный поиск магов в промежутке возрастов через `@RequestParam`. Фильтрация выполняется силами СУБД (Java Streams полностью удалены).
* `GET /student/{id}/faculty` — Получить факультет, к которому привязан конкретный студент (в одну строчку, используя ленивую загрузку).

### Факультеты (`/faculty`)
* Полный CRUD-цикл (`POST` возвращает только `Long id` со статусом 201, `GET` возвращает объект, `PUT` возвращает обновленный объект, `DELETE` возвращает `void` со статусом 204).
* `GET /faculty?nameOrColor=Gryff` — Универсальный регистронезависимый поиск по подстроке в имени или цвете силами СУБД.
* `GET /faculty/{id}/student` — Получить список всех студентов, обучающихся на конкретном факультете (коллекция выгружается лениво по требованию).

### Аватарки и файлы (`/avatar`) — Реализовано в ДЗ 3.5
* `POST /avatar/{studentId}` — Загрузить аватарку студента через форму `MultipartFile`. Файл сохраняется параллельно на локальный диск Mac в буферную папку и в виде бинарного массива байт `byte[]` в PostgreSQL (поле `@Lob`). Метод возвращает чистый `Long id` аватарки со статусом `201 Created` без использования `ResponseEntity`.
* `GET /avatar/{studentId}/from-db` — Скачать аватарку студента напрямую из базы данных PostgreSQL. Возвращает массив байт с корректным прописыванием `HttpHeaders` (`Content-Type` и `Content-Length`) для распознавания файловым движком Mac. Легальное использование `ResponseEntity`.
* `GET /avatar/{studentId}/from-file` — Высокопроизводительное скачивание аватарки транзитом с жесткого диска через `HttpServletResponse.getOutputStream()` с использованием буферизированного метода `transferTo()`. Подход полностью защищает оперативную память кучи `Heap` от перегрузки тяжелыми массивами байт.

## 🏗️ 4. Блок: Автоматическое тестирование веб-приложений (ДЗ 3.6)
Кодовая база проекта была полностью покрыта автоматическими тестами в двух изолированных параллельных ветках Git.

### 🟥 Подход А. Сквозное интеграционное тестирование (Ветка `homework-test-resttemplate`)
Тестирование выполнено силами фреймворка **JUnit 5** и инструмента **TestRestTemplate** с реальным подключением к СУБД **PostgreSQL 15**.
* Приложение запускается в полноценном контексте на случайном порту оперативной памяти `RAM` (`webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT`), что изолирует тестовые запуски от боевого сервера и предотвращает конфликты портов на машине разработчика.
* Полностью покрыты CRUD-операции для `StudentController` и `FacultyController`.
* Интегрирована система каскадной стерильной очистки репозиториев (`avatarRepository.deleteAll()` перед `studentRepository.deleteAll()`) для предотвращения блокировок целостности данных СУБД по внешним ключам (Foreign Key Constraints) из-за связанных сущностей аватарок.

### 🟩 Подход Б. Изолированное тестирование веб-слоя (Ветка `homework-test-mockmvc`)
Тестирование выполнено силами аннотации **@WebMvcTest** и эмулятора **MockMvc** в абсолютном отрыве от базы данных и сетевых интерфейсов.
* Слой бизнес-логики (`StudentService` / `FacultyService`) полностью замещён виртуальными роботами-заглушками **@MockBean**.
* Поведение заглушек жёстко запрограммировано через сценарии `Mockito.when().thenReturn()` и `Mockito.doNothing()`, что позволяет проверять логику контроллеров в стерильном вакууме.
* Сетевые адреса и входящие параметры верифицируются через инструмент `MockMvcRequestBuilders`, а ответы серверов парсятся по строгим JSON-путям с учётом правильной индексации массивов коллекций (например, `$[0].color` для извлечения свойств из возвращаемого списка).

## 🎛️ 5. Централизованная обработка исключений (Глобальный перехват)
В архитектуру обоих контроллеров успешно интегрированы централизованные методы-перехватчики ошибок:
```java
@ExceptionHandler(IllegalArgumentException.class)
@ResponseStatus(HttpStatus.BAD_REQUEST)
public String handleIllegalArgumentException(IllegalArgumentException ex) {
    return ex.getMessage();
}
```
* **Физика процесса:** При возникновении промаха по базе данных (например, запрос несуществующего ID), слой сервисов выбрасывает исключение `IllegalArgumentException`. Аннотация `@ExceptionHandler` перехватывает эту аварию прямо в памяти RAM, блокирует стандартное падение сервера в ошибку 500, наклеивает сетевой штамп клиентской ошибки `400 Bad Request` и возвращает чистый, понятный текст ошибки клиенту через `ex.getMessage()`. Это полностью удовлетворяет критериям промышленной отказоустойчивости веб-приложений.

## 🖥️ 7. Запуск, Окружение и Аудит Инфраструктуры

### ⚠️ Критически важные требования к окружению (Закон Аудита)
Проект требует строгого соответствия настроек инфраструктуры на локальном компьютере:
1. **Кодировка файлов:** Файлы конфигурации `application.properties` (как в директории `main`, так и в `test`) должны быть строго сохранены в кодировке `UTF-8` с типом перевода строк `LF` (настройка в правом нижнем углу IntelliJ IDEA). Потеря типа файла или скрытые байты переноса CRLF приводят к падению контекста Spring!
2. **Переменные окружения:** В конфигурации запуска проекта (`Edit Configurations` -> `Environment variables`) должна быть жестко вшита переменная пути к файлам: `path.to.avatars.folder=./avatars`.

> 🛑 **Закон защиты от зацикливания:** При любых инфраструктурных сбоях (например, ошибках "Could not resolve placeholder") категорически запрещено циклически переписывать рабочий Java-код. Наставник и разработчик обязаны пошагово отсекать внешние факторы окружения: кодировку файлов -> очистку кэша сборщика (`Maven Clean`) -> проверку переменных окружения в IDE -> права доступа macOS на чтение/запись директории `./avatars`.

### 📌 Порядок запуска приложения
1. Выровняйте и отформатируйте код: нажмите комбинацию горячих клавиш **⌥⌘L** (`Option + Command + L`).
2. Скомпилируйте проект без запуска веб-сервера для проверки здоровья синтаксиса: нажмите **⌘F9** (`Command + F9`).
3. Запустите главный класс приложения `SchoolApplication` кликом по кнопке графического интерфейса (GUI) в IntelliJ IDEA. Встроенный сервер **Tomcat** поднимется на порту `8080`.
4. Откройте интерактивный фронтенд Swagger UI в браузере для тестирования эндпоинтов:
   `http://localhost:8080/swagger-ui/index.html`
