# Hogwarts School API 🧙‍♂️✨

Веб-приложение для управления цифровой картотекой школы магии и волшебства «Хогвартс». Проект реализован на фреймворке *
*Spring Boot 3.3.0** с использованием архитектуры **MVC** (Model-View-Controller).

## 🚀 Стек технологий

* **Java 17** (Amazon Corretto)
* **Spring Boot 3.3.0** (Web, Spring Data JPA [спринг дэ́йта джей-пи-эй])
* **PostgreSQL 15** [по́стгрэс кью-эл] (Реляционная база данных для вечного хранения сущностей)
* **Hibernate / ORM** [хайбэрне́йт] (Автоматическое управление схемами таблиц в режиме `update` [апде́йт])
* **Maven** [мэ́йвен] (Сборщик проекта)
* **Springdoc OpenAPI v2 (Swagger UI)** [сва́гэр ю-ай] (Интерактивная документация API)
* **Git / GitHub** [гит / гитха́б] (Система контроля версий)

## 🏗️ Архитектура проекта

Проект разделен на четыре независимых слоя по стандарту Enterprise-разработки:

1. `model` [мо́дэл] (Слой данных) — реляционные сущности `Student` [сту́дент], `Faculty` [фэ́кэлти] и `Avatar` [э́вэтар]
   с объектными связями `@ManyToOne` / `@OneToMany` и `@OneToOne` [эт уа́н ту уа́н — один к одному], защищёнными ленивой
   загрузкой `FetchType.LAZY` [фэтч тайп лэ́йзи] для предотвращения переполнения оперативной памяти RAM и ошибок
   `OutOfMemoryError` [а́ут оф мэ́мори иксе́пшн].
2. `repository` [репо́зитори] (Слой доступа к БД) — интерфейсы, наследующие `JpaRepository` [джей-пи-эй репо́зитори] для
   автоматической генерации быстрых SQL-запросов [эс-кью-эл запро́сов]. Filter-методы полностью переведены на нативный
   SQL-движок базы данных.
3. `service` [се́рвис] (Слой бизнес-логики) — компоненты `@Service` [эт се́рвис], управляющие логикой через БД и потоки
   ввода-вывода `I/O Streams` [ай-оу стримз]. На уровне сервисов реализована жесткая страховка от `null` [нал] значений
   в Heap через выброс контролируемых `IllegalArgumentException` [илли́гл а́ргумэнт иксе́пшн].
4. `controller` [контро́ллер] (Веб-слой) — сетевые диспетчеры `@RestController` [эт рэст контро́ллер] для обработки
   HTTP-запросов по REST-стандарту. Согласно критериям кураторов SkyPro, контроллеры находятся "на диете" (логика
   содержит строго одну строку вызова сервиса), а использование `ResponseEntity` [рэспо́нс э́нтити] запрещено везде,
   кроме эндпоинтов выгрузки бинарных файлов.

## 🛠️ Функционал API (CRUD + Фильтрация и Связи)

### Студенты (`/student`)

* `POST /student` — Создать студента. Возвращает строго чистый `Long id` [лонг ай-ди] со статусом `201 Created` (через
  `@ResponseStatus`). Использование `ResponseEntity` запрещено.
* `GET /student/{id}` — Получить полную информацию о студенте по его ID из базы данных (защищено от `null`).
* `PUT /student` — Обновить данные мага. Возвращает полностью обновленный объект сущности (все поля).
* `DELETE /student/{id}` — Удалить карточку студента из PostgreSQL. Возвращает `void` [войд] со статусом
  `204 No Content` (через `@ResponseStatus`).
* `GET /student?min=10&max=15` — Оптимизированный поиск магов в промежутке возрастов через
  `@RequestParam` [эт рэ́квэст пара́м]. Фильтрация выполняется силами СУБД (Java Streams полностью удалены).
* `GET /student/{id}/faculty` — Получить факультет, к которому привязан конкретный студент (в одну строчку через сервис,
  используя ленивую загрузку).

### Факультеты (`/faculty`)

* Полный CRUD-цикл (`POST` возвращает только `Long id` со статусом 201, `GET` возвращает объект, `PUT` возвращает
  обновленный объект, `DELETE` возвращает `void` со статусом 204).
* `GET /faculty?nameOrColor=Gryff` — Универсальный регистронезависимый поиск по подстроке в имени или цвете факультета
  силами СУБД.
* `GET /faculty/{id}/student` — Получить список всех студентов, обучающихся на конкретном факультете (коллекция
  выгружается лениво по требованию).

### Аватарки и файлы (`/avatar`) — Реализовано в ДЗ 3.5

* `POST /avatar/{studentId}` — Загрузить аватарку студента через форму `MultipartFile` [ма́лтипарт файл]. Файл
  сохраняется параллельно на локальный диск Mac в буферную папку и в виде бинарного массива байт `byte[]` в таблицу
  PostgreSQL (поле `@Lob` [эт лоб]). Метод возвращает чистый `Long id` аватара со статусом `201 Created` (без
  `ResponseEntity`).
* `GET /avatar/{studentId}/from-db` — Скачать аватарку студента напрямую из базы данных PostgreSQL. Возвращает массив
  байт с корректным прописыванием `HttpHeaders` (`Content-Type` и `Content-Length`) для распознавания файла браузером (
  легальное использование `ResponseEntity`).
* `GET /avatar/{studentId}/from-file` — Высокопроизводительное скачивание аватарки транзитом с жесткого диска Mac через
  `HttpServletResponse.getOutputStream()` с использованием буферизированного метода `transferTo` [трэ́нсфэр ту].
  Полностью защищает оперативную память кучи `Heap` от перегрузки тяжелыми массивами байт.

## 📊 Аналитика и Базы Данных

В корне проекта создан файл `scripts.sql` [скриптс эс-кью-эл], содержащий каноничные SELECT-запросы [сэле́кт запро́сов]
на чистом языке SQL для прямой аналитической работы с таблицами через pgAdmin 4 [пи-джи адми́н фо].

## 🖥️ Запуск, Окружение и Аудит Инфраструктуры

### ⚠️ Критически важные требования к окружению (Закон Аудита)

Проект требует строгого соответствия настроек инфраструктуры на локальном компьютере:

1. **Кодировка файлов**: Файл `application.properties` должен быть строго сохранен в кодировке `UTF-8` с типом перевода
   строк `LF` (настройка в правом нижнем углу IntelliJ IDEA). Потеря типа файла или скрытые байты переноса строк
   приводят к падению контекста Spring!
2. **Переменные окружения**: В конфигурации запуска проекта (`Edit Configurations` -> `Environment variables`) в строку
   запуска должна быть жестко вшита переменная пути к файлам: `path.to.avatars.folder=./avatars`.

> 🛑 **Закон защиты от зацикливания:** При любых инфраструктурных сбоях (например, ошибках "Could not resolve
> placeholder") категорически запрещено циклически переписывать рабочий Java-код. Наставник и разработчик обязаны
> пошагово
> отсекать внешние факторы окружения: кодировку файлов -> очистку кэша сборщика (`Maven Clean` [мэ́йвэн клин]) ->
> проверку
> переменных окружения в IDE -> права доступа macOS на чтение/запись директории `./avatars`.

### 🚀 Порядок запуска

1. Выровняйте и отформатируйте код: нажмите комбинацию горячих клавиш **Option + Command + L (⌥⌘L)**.
2. Скомпилируйте проект без запуска веб-сервера для проверки здоровья синтаксиса: нажмите **Command + F9 (⌘F9)**.
3. Запустите главный класс приложения `SchoolApplication` [скул апплике́ишн] кликом по кнопке графического интерфейса (
   GUI) в IntelliJ IDEA. Встроенный сервер **Tomcat** [то́мкэт] поднимется на порту `8080`.
4. Откройте интерактивный фронтенд Swagger UI в браузере для тестирования эндпоинтов:
   `http://localhost:8080/swagger-ui/index.html`
