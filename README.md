# 🧙‍♂️ Hogwarts School API — Enterprise Management System

Промышленное веб-приложение для комплексной автоматизации и управления цифровой картотекой Школы Чародейства и
Волшебства «Хогвартс». Проект реализован на фреймворке **Spring Boot 3.3.0** с использованием отказоустойчивой слоеной
архитектуры **MVC** (Model-View-Controller) и объектно-реляционного отображения (ORM).

---

## 🚀 1. Стек технологий и Системное Окружение

* **Java 17** (Amazon Corretto) — среда исполнения виртуальной машины (JVM).
* **Spring Boot 3.3.0** (Web, Starter Data JPA, Starter Test) — ядро экосистемы приложения.
* **PostgreSQL 15** — промышленная реляционная система управления базами данных (СУБД).
* **Hibernate / JPA** — движок ORM для автоматического управления схемами таблиц в режиме `update`.
* **Maven** — автоматизированный сборщик проекта и управление внешними зависимостями.
* **Jackson (ObjectMapper)** — сериализация и десериализация объектов в текстовый JSON-формат.
* **Springdoc OpenAPI v2 (Swagger UI)** — интерактивный фронтенд документации и тестирования API.
* **JUnit 5 / AssertJ / Mockito** — стек модульного, веб-изолированного и сквозного интеграционного тестирования.

## 🏗️ 2. Архитектура проекта и Слоевая Изоляция

Проект разделен на четыре независимых слоя для минимизации зацепления (coupling) и обеспечения строгой инкапсуляции
данных:

1. `model` (Слой данных) — реляционные сущности `Student`, `Faculty` и `Avatar` со связями `@ManyToOne`, `@OneToMany` и
   `@OneToOne`. Все объектные графы защищены ленивой загрузкой `FetchType.LAZY` для предотвращения переполнения
   оперативной памяти RAM и критических ошибок `OutOfMemoryError`.
2. `repository` (Слой доступа к БД) — интерфейсы, наследующие `JpaRepository`. Аналитические и фильтрационные методы
   переведены на нативный высокопроизводительный SQL-движок базы данных через аннотации `@Query(nativeQuery = true)`.
3. `service` (Слой бизнес-логики) — компоненты `@Service`, управляющие логикой через БД и потоки ввода-вывода
   `I/O Streams`. На уровне сервисов реализована жесткая страховка от `null`-значений в памяти Heap через автоматический
   выброс контролируемых `IllegalArgumentException`.
4. `controller` (Веб-слой) — сетевые диспетчеры `@RestController` для обработки HTTP-запросов по REST-стандарту.
   Контроллеры находятся на строгой «диете» (логика метода содержит строго одну строку вызова сервиса), а использование
   `ResponseEntity` запрещено везде, кроме эндпоинтов выгрузки бинарных файлов.

## 🛠️ 3. Спецификация API (CRUD, Нативная Аналитика и Веб-Пагинация)

### Студенты (`/student`)

* `POST /student` — Создать карточку студента. Возвращает строго чистый `Long id` со статусом `201 Created` (
  `@ResponseStatus`).
* `GET /student/{id}` — Получить полную информацию о студенте по его ID из базы данных (защищено от `null`).
* `PUT /student` — Обновить данные мага. Возвращает полностью обновленный объект сущности (все поля).
* `DELETE /student/{id}` — Удалить карточку студента из PostgreSQL. Возвращает `void` со статусом `204 No Content` через
  `@ResponseStatus`.
* `GET /student?min=10&max=15` — Оптимизированный поиск магов в промежутке возрастов через `@RequestParam`. Фильтрация
  выполняется силами СУБД (Java Streams полностью удалены).
* `GET /student/{id}/faculty` — Получить факультет, к которому привязан конкретный студент (используя ленивую загрузку).
* `GET /student/count` — Нативный агрегатный подсчет общего количества студентов в школе силами СУБД (
  `SELECT COUNT(*)`). Возвращает число.
* `GET /student/average-age` — Нативный расчет среднего возраста студентов (`SELECT AVG(age)`). Содержит бизнес-защиту
  на уровне сервиса: возвращает `0.0`, если база данных пуста.
* `GET /student/last-five` — Выгрузка строго 5 последних созданных студентов по критерию максимального ID (
  `SELECT * FROM student ORDER BY id DESC LIMIT 5`).

### Факультеты (`/faculty`)

* Полный CRUD-цикл (`POST` возвращает только `Long id` со статусом 201, `GET` возвращает объект, `PUT` возвращает
  обновленный объект, `DELETE` возвращает `void` со статусом 204).
* `GET /faculty?nameOrColor=Gryff` — Универсальный регистронезависимый поиск по подстроке в имени или цвете силами СУБД.
* `GET /faculty/{id}/student` — Получить список всех студентов, обучающихся на конкретном факультете (коллекция
  выгружается лениво по требованию).

### Аватарки и файлы (`/avatar`)

* `POST /avatar/{studentId}` — Загрузить аватарку студента через форму `MultipartFile`. Файл сохраняется параллельно на
  локальный диск в буферную папку и в виде бинарного массива байт `byte[]` в PostgreSQL (поле `@Lob`). Метод возвращает
  чистый `Long id` аватарки со статусом `201 Created`.
* `GET /avatar/{studentId}/from-db` — Скачать аватарку студента напрямую из базы данных PostgreSQL. Возвращает массив
  байт с корректным прописыванием `HttpHeaders` (`Content-Type` и `Content-Length`) для распознавания файловым движком
  операционной системы.
* `GET /avatar/{studentId}/from-file` — Высокопроизводительное скачивание аватарки транзитом с жесткого диска через
  `HttpServletResponse.getOutputStream()` с использованием буферизированного метода `transferTo()`. Подход полностью
  защищает оперативную память кучи `Heap` от перегрузки тяжелыми массивами байт.
* `GET /avatar?page=0&size=5` — Постраничный вывод списков аватарок из репозитория. Параметры страницы и размера пачки
  принимаются через `@RequestParam`. На уровне репозитория задействован механизм `Pageable` и интерфейс `Page<Avatar>`,
  извлекающий чистый список через метод `.getContent()`. Защищает память RAM от перегрева при больших объемах данных.
  Нумерация страниц начинается с 0.

## 🏗️ 4. Стратегия Автоматического Тестирования

Кодовая база проекта полностью покрыта автоматическими тестами с использованием двух различных архитектурных подходов.

### 🟥 Подход А. Сквозное интеграционное тестирование

Тестирование выполнено силами фреймворка **JUnit 5** и инструмента **TestRestTemplate** с реальным подключением к СУБД *
*PostgreSQL 15**.

* Приложение запускается в полноценном контексте на случайном порту оперативной памяти `RAM` (
  `webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT`), что изолирует тестовые запуски от боевого сервера и
  предотвращает конфликты портов на машине разработчика.
* Полностью покрыты CRUD-операции для `StudentController` и `FacultyController`.
* Интегрирована система каскадной стерильной очистки репозиториев (`avatarRepository.deleteAll()` перед
  `studentRepository.deleteAll()`) для предотвращения блокировок целостности данных СУБД по внешним ключам (Foreign Key
  Constraints).

### 🟩 Подход Б. Изолированное тестирование веб-слоя

Тестирование выполнено силами аннотации **@WebMvcTest** и эмулятора **MockMvc** в абсолютном отрыве от базы данных и
сетевых интерфейсов.

* Слой бизнес-логики (`StudentService` / `FacultyService`) полностью замещён виртуальными заглушками **@MockBean**.
* Поведение заглушек жёстко запрограммировано через сценарии `Mockito.when().thenReturn()` и `Mockito.doNothing()`, что
  позволяет проверять логику контроллеров в стерильном вакууме.
* Сетевые адреса и входящие параметры верифицируются через инструмент `MockMvcRequestBuilders`, а ответы серверов
  парсятся по строгим JSON-путям с учётом правильной индексации массивов коллекций.

## 🎛️ 5. Глобальная обработка исключений

В архитектуру контроллеров интегрированы централизованные методы-перехватчики ошибок:

```java

@ExceptionHandler(IllegalArgumentException.class)
@ResponseStatus(HttpStatus.BAD_REQUEST)
public String handleIllegalArgumentException(IllegalArgumentException ex) {
    return ex.getMessage();
}
```

* **Физика процесса:** При возникновении промаха по базе данных (например, запрос несуществующего ID), слой сервисов
  выбрасывает исключение `IllegalArgumentException`. Аннотация `@ExceptionHandler` перехватывает эту аварию прямо в
  памяти RAM, блокирует стандартное падение сервера в ошибку 500, наклеивает сетевой штамп клиентской ошибки
  `400 Bad Request` и возвращает чистый, понятный текст ошибки клиенту через `ex.getMessage()`. Это полностью
  обеспечивает промышленную отказоустойчивость веб-приложений.

## 🖥️ 7. Запуск, Инфраструктура и Локальное Окружение

### ⚠️ Критически важные требования к окружению

Проект требует строгого соответствия настроек инфраструктуры на локальной рабочей машине:

1. **Кодировка файлов:** Файлы конфигурации `application.properties` (как в директории `main`, так и в `test`) должны
   быть строго сохранены в кодировке `UTF-8` с типом перевода строк `LF` (настройка в правом нижнем углу IntelliJ IDEA).
   Потеря типа файла или скрытые байты переноса CRLF приводят к падению контекста Spring!
2. **Параметры запуска VM options:** Для гарантированного обхода локальных конфликтов кэша IDE, параметры подключения к
   PostgreSQL и путь к аватарам передаются в память виртуальной машины напрямую через `Edit Configurations` ->
   `VM options` флагами `-D`:
   `-Dspring.datasource.url=jdbc:postgresql://localhost:5432/hogwarts -Dspring.datasource.username=student -Dspring.datasource.password=chocolatefrog -Dpath.to.avatars.folder=./avatars`
3. 🛑 **Закон защиты от зацикливания:** При любых инфраструктурных сбоях (например, ошибках "Could not resolve
   placeholder") категорически запрещено циклически переписывать рабочий Java-код. Разработчик обязан пошагово отсекать
   внешние факторы окружения: кодировку файлов -> очистку кэша сборщика (`Maven Clean`) -> проверку переменных окружения
   в IDE -> права доступа операционной системы на чтение/запись директории `./avatars`.

### 📌 Порядок запуска приложения

1. **Форматирование:** Выровняйте и отформатируйте код во всем проекте, нажав комбинацию горячих клавиш **⌥⌘L** (
   `Option + Command + L`).
2. **Компиляция:** Скомпилируйте проект без запуска веб-сервера для полной проверки здоровья синтаксиса, нажав **⌘F9** (
   `Command + F9`).
3. **Старт:** Запустите главный класс приложения `SchoolApplication` кликом по кнопке запуска графического интерфейса (
   GUI) в IntelliJ IDEA (или через сочетание **⌃R**). Встроенный сервер **Tomcat** поднимется в оперативной памяти RAM
   на порту `8080`.
4. **Тестирование:** Откройте интерактивный веб-интерфейс Swagger UI в любом браузере для визуального тестирования
   аналитических эндпоинтов и пагинации по адресу:  
   `http://localhost:8080/swagger-ui/index.html`
